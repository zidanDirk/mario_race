# 方案二：计时挑战与个人幽灵

已完成独立计时模式、个人最佳幽灵回放、十二段累计差值、独立云端排行榜。保留原有道具竞速及双捷径机关。

## 体验

- 菜单选择计时挑战，单人完成三圈；首跑建立本机最佳，再跑出现半透明青蓝赛车，暂停同步冻结，可关闭显示。
- 每圈四段，用负数/正数表达比此前最佳更快/更慢；结算可滚动查看全部十二段。
- 只保存更快的完整录像，重开或慢成绩不覆盖最佳。刷新可恢复；禁用存储、坏数据或空间不足不会阻塞比赛。
- 计时关闭 AI 和随机道具，保留漂移、金币、加速、捷径与机关；切回道具竞速恢复六车与道具箱。
- 比赛模式绑定服务端开赛凭证。两种模式分别统计排名与最佳，查看另一排行榜不改变当前比赛。旧数据库记录迁移为道具竞速。

## 验证

- 生产构建通过，全部 52 组确定性游戏检查通过（原有 43 组 + 9 组幽灵检查）。
- 15 组后端 HTTP/SQLite 检查通过，覆盖旧库迁移与重启、十二用户的两套前十榜、模式篡改及计时位置校验。
- [实际键盘浏览器检查](browser.json)：两次完整三圈，首跑 47.166 秒、再跑 49.500 秒；分别记录十二分段，慢成绩保留首跑的 945 帧录像（66,191 字节）。暂停、重开、显隐、无碰撞、刷新恢复、手机布局和切回竞速通过，页面错误为空。
- [真实本地 API 浏览器检查](cloud/browser.json)：9 组通过，覆盖登录、全屏、开赛、保存失败重试、独立模式统计/榜单、刷新、手机、退出和 QA 禁止上传。道具竞速 62 秒与计时 57 秒分别回读，数据库只有两条已完成比赛。
- 最后仅补充操作指南、模式说明和隐藏计时模式的无效道具快捷键提示；构建再次验证。未重跑与本次无关的旧专项浏览器套件。

## 边界

幽灵轨迹只保存在本浏览器，不跨设备同步；云端保存成绩。真实微信/Google 凭据和阿里云服务器尚未提供，未进行真实第三方登录或部署。成绩仍由客户端计算，服务端提供基础校验而非完整防作弊。手机采用桌面 Chrome 尺寸仿真，未验证实体手机/手柄性能。Three.js 主包超过 500 kB 的现有构建提示仍存在。
