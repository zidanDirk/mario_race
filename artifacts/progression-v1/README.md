# 方案三：车手成长与每日挑战

首版已实现六种任务模板、每日三个任务和三档外观奖励。入口位于顶部「✦ 每日挑战」，比赛中打开会暂停。具体规则见 [设计约定](design.md)。

## 功能与边界

任务包括完赛、橙色及以上漂移释放、单场十枚金币、无救援完赛、捷径出口加速和计时完赛。北京时间零点轮换，登录玩家的开赛凭证同步服务器当天任务；跨日仍按开赛日期结算。只有完整完赛才累计任务，每项100 XP、每天最多300 XP，重复提交不重复领奖。

100 XP 解锁薄荷车漆，300 XP 解锁紫色尾焰，600 XP 解锁星光车手称号。装备跟随玩家选择的赛车，对手车漆保持原样，尾焰在加速时显示；称号进入个人标签与账号榜单。所有奖励只改变渲染，不改变运动、道具和计分。

游客独立保存在本浏览器，登录后使用服务器账号数据，互不合并；账号经验与装备可跨设备读取，幽灵仍只保存在本机。网络保存失败不假发云端奖励，成绩重试与装备重试均有反馈。生产第三方OAuth和阿里云部署仍待用户配置，当前验证采用本地开发账号。

SQLite版本3增加 `races.metrics` 与 `user_progression`，保留既有用户、登录会话和两种模式成绩。完赛与成长写入同一事务，装备接口检查解锁权限。Docker及原生安装脚本均携带共享规则目录；未在阿里云执行部署。驾驶事件仍由客户端报告，属于基础校验而非完整防作弊。

## 验证

- [游戏确定性检查](unit-tests.txt)：全部60组通过，含8组新增共享规则检查。覆盖六模板、三任务轮换、北京时间边界、累计与单场统计区别、跨日、一次发奖、三档权限、恢复默认、坏存储与非法指标。
- [后端检查](server-tests.txt)：全部20组通过，含5组新增HTTP/SQLite检查。覆盖未登录/来源校验、旧库迁移、模式隔离、重复提交、篡改、跨午夜、数据库重启与账号隔离。
- [实际游戏浏览器检查](browser.json)：8组通过。真实键盘三圈47.067秒，经过12个分段，拾取54枚金币、无救援，获得200 XP；刷新保留，放弃比赛不领奖。另以放置场景+实际输入验证金币满格仍计数、手动/自动救援各记一次、捷径出口与真实橙色漂移（蓄力2.11）。装备、换车、恢复默认、手机布局和原竞速对手/道具均通过。
- [真实本地API浏览器联调](cloud/browser.json)：4组通过，验证服务器确认才加经验、保存重试不重复、三档解锁、装备失败保持原状、刷新恢复、称号上榜、退出恢复游客、新账号零进度。
- [加速特效检查](effects.json)：蘑菇触发紫色尾焰，恢复默认后显示原橙色；使用真实道具操作，未直接注入特效。
- TypeScript/Vite生产构建通过。现有Three.js主包仍超过500kB；本轮没有声明实体手机性能或手柄硬件验收。

最初救援浏览器检查超时，原因是旧测试点在新增捷径旁，实际只偏离道路约41米，不满足60米救援阈值。将QA放置点移到真正远离所有道路的位置后检查通过，未修改游戏的救援规则。账号联调测试也修正了填表与账号刷新之间的时序。
