# 机关战术验收

实现城堡湿滑内线、干燥绕行和周期换向的双传送带；中央保持普通路面。新增炸弹、星星，八种道具共享双格库存与键盘/触屏/手柄入口。AI 共用路面查询、提前选带、避让炸弹、按距离使用道具。云端 GP6 / TT5、本机 tactics1 / cup-v4 / elimination-v4 与旧纪录隔离，历史保留。

## 已验证

- `build.txt`：TypeScript 与 Vite 生产构建通过。主 JS 765.63 kB / gzip 226.16 kB，沿用现有大包提示；未增加依赖、外部服务或凭据。
- `unit.txt`：全量规则回归通过，包括新增路面 13 组、实际驾驶 9 组、炸弹物理 4 组，及扩展道具/AI规则。覆盖三个驾驶配置湿滑恢复，30/60/120 Hz 传送带停车、倒车、侧向和受击时运动，以及星星与传送带撞栏。
- `server.txt`：28 项后端检查通过，覆盖开赛/完赛、版本与配置绑定、旧数据、排行榜、成长。
- `browser.json`：11 组生产构建浏览器交互检查，使用显式 QA 初始场景与真实输入。传送带推动、湿滑驾驶、暂停同步、前抛/后放、一次爆炸、护栏遮挡、喇叭清弹、星星免伤/接触/到期、试驾重开/退出/零存储、手机横竖屏道具、模拟标准手柄长按不连发。浏览器异常为 0。
- `production.json`：普通 URL 无 QA 接口，测试账号开赛 GP6 / TT5 与配置一致，真实 20 秒城堡试驾不写成绩，实际 HTTP 完赛接口及榜单显示通过。该完赛接口检查使用明确服务端时间夹具；不作为真实驾驶证据。

完整城堡三圈通过，时间 63.417 秒、0 意外救援、0 护栏撞击、0 浏览器异常。AI 实际经过湿地和传送带，并分别使用炸弹和星星；玩家实际拾取 9 个道具并投出炸弹。峰值 308 draw calls / 373,276 triangles，属于桌面 Chrome 测量。完整数据记录于 `race.json`。测试通过杯赛首站的显式完赛夹具进入城堡，城堡内只使用真实键盘加速、刹车、转向和道具键，不注入位置、时间或完赛状态。包含第二站结算与整杯重开清理。

## 画面与操作

已查看湿滑行驶、传送带顺向/换向预警、炸弹范围、星星保护、390×844 竖屏与 844×390 横屏截图。提示不遮挡转向、加速、漂移、道具按钮。采用已有 Playwright 状态截图与真实驾驶脚本；本次不引入整图像素断言。路面装饰使用 21 个 mesh，传送带箭头使用实例化；星星与爆炸特效采用固定对象池，炸弹危险圈材质在清理时释放。

首轮验收发现 5173 已被另一个坦克游戏占用，因此保持其运行，在 5180 启动赛车开发预览、5181 启动固定生产预览。另修正测试脚本在点击返回/重开后未等待下一帧的问题；未改动游戏规则以规避测试。复查调整湿地区域提示为「干燥外线」，避免左右方向误导。

真实手机、实体手柄、微信/Google 正式 OAuth、阿里云部署尚未验证。模拟输入和桌面渲染开销不代表实体手机性能。本次不改变已有 CDN 相对路径和发布配置。

复现：`npm run build`，启动 `npx vite preview --host 127.0.0.1 --port 5181`，执行 `GAME_URL=http://localhost:5181 npm run test:tactics`；测试顺序执行以避免多个 WebGL 实例争抢 GPU。`CHROME_PATH` 可指定 Chrome 可执行文件。
