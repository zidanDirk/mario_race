# 漏点恢复体验优化 · 2026-09-16

用户截图为检查点顺序校验未通过时的提示。其具体驾驶路线无法从截图还原；目前实际主路、路边和两条捷径测试未复现合法行驶漏点。确认的体验问题是没有可点击的解决入口、无法看出漏点位置，旧手动救援还可能退回很远的安全点。

## 复现与判断

修复前 `node tests/checkpoint-browser.mjs` 用原有 `setupDetour('missed')` 进入与截图一致的状态，检查恢复按钮时报 `false !== true`。这是 UI 入口缺失的实际失败信号，并非假设底层计点一定有错。

独立规则测试 `node --experimental-strip-types tests/checkpoints.mjs` 检查两条真实曲线赛道的五条横向行驶线，并核对漏点后的返回距离。正常顺序计点通过；旧救援在保留很早安全点的场景中，分别返回到漏点前 93.6 / 113.6 米，定位了「回去后仍要跑很远」的恢复体验问题。既有 course 测试的主路/捷径顺序计点、反向和越段反作弊检查也通过。

## 修改

- 增加明确说明与「回到检查点前」按钮，鼠标、触屏、键盘焦点操作均可使用；小地图用橙圈与无障碍标签标明目标。
- 漏点时按 Backspace 或标准手柄 Select / − 使用同一恢复逻辑；重复按键及持续按住手柄只触发一次。
- 返回检查点前约 8 米，车头朝正向，保留原 nextGate，必须实际开过才能补点。保留计时、最多扣 3 金币及原有短暂救援保护；清除漂移、跳台、尾流与按键状态。
- 不自动移动路面上的车辆；暂停不恢复，退出清理提示。横屏使用紧凑双栏，手机提示不遮挡计时器和驾驶按钮。

## 验证

- `build.txt`：TypeScript / Vite 生产构建通过，保留既有包大小提醒。
- `unit.txt`：完整规则测试通过，包含新增四组检查点测试，以及既有驾驶/碰撞/捷径/跳台/圈数检查。
- `browser.json`：6 组实际浏览器交互通过，异常 0。覆盖等待不传送且计时继续、鼠标返回后真实 W 加速补点、金币仅扣一次、Backspace、390×664 / 844×390 触屏、模拟标准手柄、暂停/返回首页。
- `desktop.png`、`mobile.png`、`landscape.png`、`recovered.png` 已检查，恢复按钮至少 44 px 高，提示与计时区域不重叠，页面无横向溢出。

浏览器用测试夹具创建漏点状态，恢复与补点均走真实输入/游戏逻辑。实体手机和实体手柄未验证。本次保留检查点判定和成绩规则版本，不将未知驾驶轨迹武断归因为系统误判。
