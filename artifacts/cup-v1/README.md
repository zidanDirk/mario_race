# 城堡夜赛与双站杯赛验收

方案二技巧连击已完成；本次实现方案三：新城堡夜赛和两站累计积分杯赛。设计见 design.md。

## 已实现

- 提取 tracks.ts 赛道点、道具、金币、加速点、宽度配置；原蘑菇赛道几何保持不变。
- Castle Night 环线 987.783 米，最小曲率半径 25.284 米，12 米窄桥及15米入口/出口渐变；城门、塔楼、火把、月夜、护城河、青色引导与共用端点的护栏碰撞。
- 菜单「双站杯赛」，六名固定车手、固定难度，两站各三圈；积分15/12/10/8/6/4。同分比较获胜次数、名次总和、末站名次；按玩家冲线时的实际赛况结算各站，不编造AI用时。
- 中场积分和手动下一站；重跑当前站回滚当前结果，保留已完成前站；最终领奖台及全部车手积分；退出杯赛回到蘑菇赛道。
- 两个场景按需缓存，切站更新道路采样、护栏、驾驶/检查点、地图、灯光、道具和技巧状态。城堡AI车道跟随收窄的桥面。返回计时模式恢复原蘑菇轨道和无AI/道具规则。
- 杯赛及其每站技巧纪录仅存本机，与单场榜和每日成长隔离。同难度上届成绩可在杯赛菜单回看，失败存储有提示。

## 验证

- 生产构建通过，主JS约698kB/201kB gzip，保留既有大包提示；没有新增运行时依赖。
- `npm run test:unit` 通过121项确定性检查，包括原101项、14项杯赛状态/重复提交/重跑/平局、6项赛道几何/道路收窄/护栏/物品/三圈驾驶检查。见 unit.txt。
- `tests/cup-browser.mjs` 通过6组浏览器检查：角色/难度保持、中场积分55、重赛撤销、窄桥真实碰撞、切换实际地图和车辆状态、最终总分110、手机表格/领奖台/重赛、本机保存、回到原计时、场景缓存最多2个。近终点场景仅用于生命周期边界，不冒充完整比赛。见 browser.json。
- `tests/cup-race-browser.mjs` 从普通首页按钮开始，通过真实键盘转向/刹车/加速完成两站共六圈，再验积分和完整重赛。无位置/圈数/道具注入，无意外救援；城堡实际穿过窄桥，AI道具生效。见 races.json。
- mushroom：真实键盘三圈 48.483 秒，救援 0；AI 取箱 14 次、使用道具 6 次。渲染采样峰值 386 calls / 527,084 triangles（含阴影与车手，非纯场景预算）。
- castle：真实键盘三圈 61.450 秒，救援 0；AI 取箱 21 次、使用道具 14 次。渲染采样峰值 288 calls / 373,224 triangles（含阴影与车手，非纯场景预算）。
- 两站实跑总积分110；耀西与奇诺比奥同为18分，按末站第3/第4名正确打破平局。用户控制的马里奥本次30分夺冠。
- `tests/cup-production.mjs` 使用生产dist与真实临时本地HTTP/SQLite：登录后的普通单场发出1个真实比赛凭证，改玩杯赛后不新增单场凭证或榜单纪录；横屏标签与计时器不重叠；禁用localStorage仍可结算并开始下一杯。2组通过，见 production.json。
- 浏览器脚本异常均为0。独立只读复查修正切回单场仍显示杯赛说明、切难度显示错误历史两处菜单状态问题。

## 使用及限制

`http://localhost:5173/?v=cup-v1` → 双站杯赛 → 开始比赛 → 下一站。首版城堡轨道通过第二站进入，尚无单独城堡计时榜。

本地开发预览开启后执行 `npm run test:cup`；构建与规则检查无需第三方服务。保持当前工程已有Google/微信登录配置与部署文件。本次没有阿里云部署、外部模型或生成服务调用；实体手机/手柄尚未测试，移动验证使用Chrome视口与指针模拟。杯赛采用玩家冲线时赛况结算，未让其余AI继续跑完或虚构完赛时间。
